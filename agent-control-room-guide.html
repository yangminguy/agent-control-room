📋 핵심 요약

✅ 완료됨 (Phase 1-5)

수동 프롬프트 생성, 계획 수립, 반자동 실행 기능이 완성되었습니다.

🔄 현재 중점 (Phase 6)

MVP 안정화, 실제 Vibe Kanban 연동, 자동화 수준 조정.

🎯 미래 (Phase 7-8)

세 에이전트 통합, 완전 자동화, 프로덕션 배포.

👤 타켓 사용자

PM 또는 비개발자가 Claude Code, Codex, Antigravity 같은 AI 코딩 도구를 사용해 제품을 구현하고 싶을 때 필요한 것들을 체계적으로 관리하는 도구입니다.

  • 무엇을 해야 할지 알고 싶다
  • 어떤 AI 도구가 할지 알고 싶다
  • 어떤 파일을 보고 편집할지 알고 싶다
  • 완료의 기준이 뭔지 알고 싶다
  • 도구 간 컨텍스트 손실을 막고 싶다

✅ 완료된 Phase들 (1-5)

DONE

Phase 1: 수동 오케스트레이션

사용자가 제품 방향을 입력하면 → 기술 번역 → 작업 분해 → 에이전트 추천 → 프롬프트 생성 → 복사 가능한 결과

구현된 것:
  • 프로젝트 등록/목록/상세 페이지
  • 마크다운 문서 파서 (AGENT_STATE.md, TASKS.md)
  • 기술 번역 및 작업 분해 (OpenAI structured output + 로컬 폴백)
  • 에이전트 라우팅 (Claude Code → Codex → Antigravity)
  • 프롬프트 생성기 (copy-ready)
  • 핸드오프 생성기
  • 세션 리포트 저장소
  • Advisor Mode (막혔을 때 분석 및 대안 제시)
DONE

Phase 2: 구조화된 계획 수립

실행 전에 "무엇을 실행하는가"를 명확히 구조화. 계획판과 Kanban 보드로 시각화.

구현된 것:
  • FeaturePlan 데이터 모델
  • PlanTask 와 상태 추적
  • KanbanCard 시각화
  • HTML 구현 계획 뷰 (/plan)
  • 칸반 보드 UI (작업 진행 상황 수동 업데이트)
DONE

Phase 3: 반자동 실행

사용자가 승인 후 버튼을 누르면 → 에이전트 실행 → 로그 스트리밍 → Git Diff 분석 → 계획 업데이트 → 다음 프롬프트

구현된 것:
  • Agent Execution Runner (Claude Code CLI 연동)
  • 안전한 Git 브랜치 생성
  • SSE 실시간 로그 스트리밍
  • Git Diff 자동 분석
  • 작업 상태 자동 업데이트 (완료/부분/실패)
  • 실행 로그 저장소
DONE

Phase 4: 멀티 에이전트 라우팅

여러 AI 도구를 목적에 따라 자동 선택. 한 에이전트가 막히면 다른 에이전트로 자동 전환.

구현된 것:
  • 에이전트 상태 추적 (available, limited, cooling_down, blocked)
  • 자동 폴백 에이전트 추천
  • 에이전트 전환 시 핸드오프 프롬프트 생성
  • /agent-status UI로 상태 수동 설정
  • 상태 변경 시 폴백 추천 표시
DONE

Phase 5: Human-Approved 루프

실행 → 분석 → 사용자 승인 → 다음 작업 → 반복. 사용자는 항상 제어권을 유지.

구현된 것:
  • 실행 완료 후 자동 Analyzer 호출
  • 판단 배지 표시 (완료/부분/대기/실패)
  • 다음 프롬프트 미리보기
  • Continue / Stop 버튼
  • /api/loop-continue 엔드포인트
  • 자동 실행 없음 - 사용자 승인 필수

📊 데이터 모델 개요

FeaturePlan

  • id, projectId
  • title, userGoal
  • status (전체 상태)
  • tasks: PlanTask[]
  • createdAt, updatedAt

PlanTask

  • id, planId, title, description
  • status (planned/ready/running/done/partial/blocked)
  • assignedAgent (Claude Code / Codex / Antigravity)
  • acceptanceCriteria[]
  • generatedPrompt, branchName
  • subAgentTracks[]

ExecutionLog

  • id, planTaskId, agent, branchName
  • startedAt, completedAt
  • exitCode, status (running/done/failed)
  • logLines[] (실시간 로그)

DiffSummary

  • changedFiles[], addedLines, removedLines
  • LLM-generated summary
  • completedTaskIds[]
  • partialTaskIds[], blockedTaskIds[]

1순위

T023: Loop UX 폴리싱 (Priority: P1)

왜: 현재 루프가 불안정하면 새 기능을 더할 때마다 기존 기능이 깨진다.

무엇: 에러 메시지 개선, 타임아웃 처리, 상태 화면 명확화, 재시도 로직

2순위

T025: 프로덕션 보안 감사 (Priority: P1)

왜: 나중에 배포할 때 보안 문제로 다시 고쳐야 한다. 지금 해결하면 향후 배포가 빠르다.

무엇: 파일 접근 권한, API 인증, XSS/CSRF 검증, 민감 정보 노출 확인

예상 소요 시간: 2-3일 (Claude Code)

3순위

T024: 실제 Vibe Kanban 연동 (Priority: P2)

왜: 드래프트만 생성하는 것은 의미가 없다. 실제 이슈가 생성되어야 의미 있다.

무엇: Vibe Kanban MCP 또는 로컬 API 호출, 이슈 자동 생성, 동기화

예상 소요 시간: 3-5일 (Claude Code 또는 Codex)

4순위

T026: Supabase 스키마 설계 (Priority: P2)

왜: 향후 배포 시 필요. 지금 설계하면 나중에 마이그레이션이 쉽다.

무엇: 테이블 정의, RLS 정책, 인덱스 설계, 마이그레이션 스크립트

예상 소요 시간: 2-3일 (Claude Code)

❓ 자주 묻는 질문

Q: 왜 아직 Supabase가 아니라 JSON을 쓰나요?

+

A: MVP는 빠른 검증이 중요합니다. JSON은 Supabase보다 설정이 간단하고, 데이터 모델이 정해진 후에 마이그레이션하면 됩니다. Phase 6에서 Supabase 스키마를 설계하고 Phase 8에서 마이그레이션합니다.

Q: Claude Code만 Runner가 있는데, 왜 Codex와 Antigravity는 아직 없나요?

+

A: Claude Code Runner가 먼저 완성되어야 반복할 수 있는 패턴이 명확해집니다. 그 패턴을 Codex (Phase 7)에 적용하고, Antigravity는 독특한 특성 때문에 별도 설계가 필요합니다.

Q: Loop UX를 먼저 하는 게 안정성에 정말 중요한가요?

+

A: 네. 현재 Loop에 버그가 있으면, Vibe Kanban을 연동할 때 원인이 뭔지 찾기 어렵습니다. 보안도 마찬가지입니다. 기초가 탄탄해야 위에 쌓는 것이 안전합니다.

Q: 전체 개발까지 얼마나 걸리나요?

+

A:

  • Phase 6 (MVP 안정화): 10-15일
  • Phase 7 (세 에이전트 통합): 15-20일
  • Phase 8 (배포 & 모니터링): 10-15일
  • 총 35-50일 (약 7-10주)
