# HERMES_OBSIDIAN_MEMORY_LOOP.md — Obsidian Memory System

## Overview

Hermes는 Obsidian을 단순 기록소가 아니라 **운영 메모리 시스템**으로 사용한다.

기록된 내용은 향후 Agent Control Room의 의사결정을 개선하는 데 재사용된다.

---

## Memory Principles

### 1. Persistent Learning

```
Agent 결과 → Hermes 분석 → Obsidian 기록 → Future 의사결정에 재사용
```

Hermes가 기록한 인사이트는 다음 Phase 계획 시에 다시 읽혀진다.

### 2. Pattern Recognition

반복되는 패턴을 감지하고 저장한다:
- 특정 파일에서 반복되는 오류
- 특정 에이전트의 성공/실패 패턴
- 특정 Phase에서 자주 발생하는 충돌

### 3. Decision Support

기록된 정보가 Agent Control Room의 에이전트 라우팅, 프롬프트 생성, 위험도 판단을 돕는다.

**원인**: RoadmapTimeline 컴포넌트의 props 정의와 사용 불일치

## Obsidian Integration Points

### 자동 생성
1. **Daily notes** → 매일 16:00 자동 생성
2. **Failure patterns** → 실패 발생 시 자동 생성
3. **Phase completion** → Phase 완료 시 자동 생성
4. **Telegram logs** → 승인 요청/응답 자동 기록

### 수동 작성
1. **Lessons learned** → Phase 완료 후 수동 추가
2. **Decision records** → Agent Control Room 판단 후 기록
3. **Pattern analysis** → 주간/월간 분석

---

## Memory Retrieval

### Agent Control Room의 메모리 사용

1. **에이전트 라우팅 개선**
   ```
   예: Claude Code의 Props 문제 패턴 → 
   다음 Phase에서 Props validation 체크 추가
   ```

2. **프롬프트 개선**
   ```
   예: 성공한 프롬프트 패턴 저장 →
   다음 유사 작업의 프롬프트에 재사용
   ```

3. **위험도 판단**
   ```
   예: 특정 파일의 반복 충돌 기록 →
   그 파일 작업 시 위험도 상향 조정
   ```

## Obsidian Sync

### 외부 시스템과의 연동

1. **Git 커밋 정보**
   - 자동으로 커밋 로그에서 추출
   - Phase 정보 링크

2. **Telegram 메시지**
   - 자동으로 저장
   - 타임스탬프 포함

3. **빌드/테스트 결과**
   - CI/CD 로그에서 자동 추출
   - 성공/실패 기록
