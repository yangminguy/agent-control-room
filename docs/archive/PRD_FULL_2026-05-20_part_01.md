# PRD: Agent Control Room

## 1. 제품 개요

### 제품명

**Agent Control Room**

### 제품 유형

오픈소스 에이전트 오케스트레이션/작업 보드 도구 위에 얹는 **개인 AI 개발 오케스트레이션 레이어**

### 한 줄 설명

기존 오픈소스 AI 코딩 작업 보드 또는 에이전트 오케스트레이션 도구를 기반으로, 사용자의 기획 의도를 기술 작업으로 번역하고 Claude Code / Codex / Antigravity를 상황에 맞게 배정·전환·핸드오프하는 개인 AI 개발 운영 시스템.

---

## 2. 핵심 방향 전환

### 기존 방향

처음부터 Agent Control Room 웹사이트와 모든 기능을 자체 구현한다.

### 수정 방향

처음부터 모든 기반 기능을 만들지 않는다.

이미 검증된 오픈소스 에이전트 오케스트레이션/작업 보드 도구를 기반으로 사용하고, 그 위에 사용자만의 오케스트레이션 레이어를 추가한다.

```txt
오픈소스 기반 도구
= 작업 보드, 에이전트 실행, git worktree, diff/review, 프로젝트 관리 기반

Agent Control Room Layer
= 기획 번역, 기술 작업 분해, AI 도구 라우팅, 프롬프트 생성, 핸드오프, 토큰 로테이션
```

---

## 3. 제품 배경

사용자는 Claude Code, Codex, Antigravity 같은 AI 코딩 도구를 동시에 사용하고 있다.

하지만 각 도구는 서로 독립적으로 작동하기 때문에 다음과 같은 문제가 발생한다.

1. 한 도구의 토큰이나 사용량이 소진되면 개발 흐름이 끊긴다.
2. 다른 도구로 이동할 때 프로젝트 맥락이 손실된다.
3. 사용자가 개발 세부사항을 직접 이해하고 지시해야 하는 부담이 크다.
4. 각 도구가 어떤 작업을 했는지 추적하기 어렵다.
5. `CLAUDE.md`, `TASKS.md`, `HANDOFF.md` 같은 프로젝트 문서가 있어도 이를 자동으로 활용하는 운영 레이어가 부족하다.
6. 기획 언어를 기술 구현 프롬프트로 바꾸는 과정이 매번 수동이다.
7. 기존 오픈소스 도구는 작업 실행과 보드 관리는 잘하지만, 사용자의 기획 언어를 기술 실행 프롬프트로 바꿔주는 레이어는 부족하다.

따라서 필요한 것은 완전히 새로운 개발 도구가 아니라, 기존 오픈소스 기반 위에서 작동하는 **AI 개발 오케스트레이션 레이어**다.

---

## 4. 핵심 문제 정의

### 현재 문제

AI 코딩 도구를 여러 개 사용하더라도, 사용자가 매번 직접 다음을 판단해야 한다.

```txt
무엇을 해야 하는가?
어떤 도구에게 맡겨야 하는가?
어떤 문서를 읽혀야 하는가?
어떤 파일을 수정하게 해야 하는가?
토큰이 다 되면 어디로 넘겨야 하는가?
결과가 제대로 된 것인가?
다음 작업은 무엇인가?
기존 오픈소스 작업 보드와 내 프로젝트 문서/토큰 로테이션 전략을 어떻게 연결할 것인가?
```

이 과정에서 사용자는 개발자가 아님에도 불구하고 기술 PM, 프롬프트 엔지니어, QA 담당자, 작업 관리자 역할을 모두 수행하게 된다.

---

## 5. 제품 목표

### 최종 목표

사용자가 제품/기획 방향만 제시하면, Agent Control Room이 이를 기술적으로 해석하고, 오픈소스 기반 도구와 Claude Code / Codex / Antigravity 중 적절한 실행 흐름에 연결한다.

### 구체 목표

1. 오픈소스 기반 도구 위에서 작동한다.
2. 사용자의 기획 언어를 기술 작업으로 번역한다.
3. 프로젝트 문서를 읽고 현재 상태를 파악한다.
4. 작업을 작은 실행 단위로 분해한다.
5. Claude Code / Codex / Antigravity 중 적합한 도구를 추천한다.
6. 각 도구에 붙여넣을 수 있는 실행 프롬프트를 생성한다.
7. 작업 결과를 받아 다음 핸드오프를 만든다.
8. 도구 간 전환 시 맥락 손실을 줄인다.
9. 사용자가 기술적으로 막혔을 때 조언자 역할을 한다.
10. 장기적으로는 토큰/사용량 상태에 따라 자동 라우팅한다.

## 6. 제품 포지셔닝

### 이 제품은 무엇인가?

**AI 코딩 툴 운영을 위한 개인용 기술 PM 시스템**

또는

**기획자/PM형 사용자를 위한 AI 개발 오케스트레이터**

또는

**오픈소스 에이전트 작업 보드 위에 얹는 개인 AI 개발 PM 레이어**

### 이 제품이 아닌 것

- 이 제품은 단순 코드 생성기가 아니다.
- 이 제품은 Claude Code, Codex, Antigravity를 대체하지 않는다.
- 이 제품은 Vibe Kanban, OpenHands 같은 오픈소스 프로젝트 관리/에이전트 실행 도구를 완전히 새로 만드는 것이 아니다.
- 이 제품은 IDE가 아니다.
- 이 제품은 자동으로 모든 개발을 완성하는 완전 자율 개발자가 아니다.

### 이 제품의 본질

```txt
기획 의도
→ 기술 요구사항
→ 작업 분해
→ AI 도구 선택
→ 실행 프롬프트 생성
→ 결과 수집
→ 핸드오프 생성
→ 다음 작업 추천
```

## 7. 오픈소스 기반 전략

### 기본 원칙

Agent Control Room은 처음부터 모든 기반 기능을 직접 구현하지 않는다.

먼저 기존 오픈소스 도구를 검토하고, 가능한 기능은 그대로 활용한다.

직접 구현하는 것은 다음에 한정한다.

```txt
기획 의도 → 기술 작업 번역
AI 도구 라우팅
실행 프롬프트 생성
HANDOFF 생성
SESSION_REPORT 정리
토큰/사용량 상태 관리
프로젝트 문서 기반 맥락 유지
비개발자용 기술 조언자 모드
```

## 8. 우선 검토 오픈소스

### 1순위 후보: Vibe Kanban

Vibe Kanban은 AI 코딩 에이전트를 작업 보드 형태로 관리하는 오픈소스 도구다.

검토 이유:

```txt
웹 기반 작업 보드 구조
Claude Code / Codex 등 코딩 에이전트와의 결합 가능성
작업 카드 중심 운영
git worktree 기반 병렬 작업 가능성
diff/review 흐름과의 연결 가능성
사용자 목표인 “AI 에이전트 가시화”와 가장 가까움
```

Agent Control Room은 Vibe Kanban을 그대로 대체하는 것이 아니라, 그 위에 다음 레이어를 추가하는 방향으로 검토한다.

```txt
사용자의 기획 입력
기술 작업 변환
AI 도구 추천
토큰 상태 기반 라우팅
도구별 프롬프트 생성
HANDOFF.md / TASKS.md / CLAUDE.md 연동
```

### 2순위 후보: OpenHands

OpenHands는 오픈소스 AI 개발 에이전트 플랫폼이다.

검토 이유:

```txt
AI 개발 에이전트 기능이 강함
로컬 GUI와 에이전트 실행 구조 참고 가능
Slack/Jira/Linear 같은 외부 연동 개념 참고 가능
```

주의점:

```txt
구조가 크고 무거울 수 있음
사용자 개인용 오케스트레이션 레이어로 커스터마이징하기에는 부담이 있을 수 있음
```

### 3순위 후보: Claude Squad

Claude Squad는 여러 AI 코딩 세션을 병렬 관리하는 터미널 중심 도구다.

검토 이유:

```txt
tmux / git worktree 기반 병렬 세션 구조 참고
여러 에이전트를 동시에 운영하는 방식 참고
```

주의점:

```txt
웹 기반 시각화가 약함
비개발자형 사용자 경험과는 거리가 있음
```

### 4순위 후보: Metaswarm

Metaswarm은 Claude Code, Codex, Gemini CLI 등 다양한 에이전트 기반 개발 흐름을 구조화하는 프레임워크다.

검토 이유:

```txt
에이전트 역할 분리
리뷰 게이트
TDD 기반 워크플로우
멀티 에이전트 SDLC 구조 참고
```

주의점:
