Agent Control Room

AI 개발 제어실 - 아키텍처 가이드

시스템 개요

Agent Control Room은 PM이나 비개발자가 개발자 없이 AI 도움말로 상품을 만들 수 있도록 돕는 시스템입니다. 아이디어를 입력하면 → 자동으로 로드맵이 생기고 → 작업이 분해되고 → 적합한 AI 도구에 보내서 → 결과를 받아서 → 다음 단계를 추천받습니다.

🎯 핵심 기능

  • ✅ 아이디어를 개발 로드맵으로 자동 변환
  • ✅ 큰 작업을 작은 단계로 분해
  • ✅ 각 단계에 맞는 AI 도구 자동 추천
  • ✅ AI 도구 결과 자동 검증
  • ✅ 위험한 작업 자동 감지 및 승인 요청
  • ✅ 다음 단계 자동 추천

⚙️ 기술 스택

프론트엔드: Next.js + TypeScript + Tailwind CSS

백엔드: Next.js API Routes

저장소: JSON 파일 (+ Supabase 선택사항)

AI 서비스: OpenAI (GPT-4), Telegram Bot

연동 도구: Claude Code, Codex, Vibe Kanban

🎚️ 자동화 레벨

🔴 수동

사용자가 직접 버튼을 눌러야 진행되는 단계

🟡 반자동

한 번의 버튼으로 여러 작업이 순차 처리됨

🟢 자동

사용자 입력 후 시스템이 자동으로 처리함

⚫ 미활성

코드는 있지만 실제로는 작동하지 않음

작업 흐름 (Workflow)

아이디어부터 완성까지 어떻게 진행되는지

1️⃣ 기획 채팅

페이지: / (홈)

수동

개발하고 싶은 기능이나 상품에 대해 자유롭게 설명합니다. 예: "사용자가 사진을 업로드하고 태그할 수 있는 갤러리 앱 만들고 싶어"

💡 여기서: 메시지 입력 → AI가 이해함 → "이 기능들이 필요해" 라고 응답

2️⃣ 계획 고정

페이지: / (홈)

수동

AI가 제안한 로드맵과 작업 분해가 마음에 들면 "계획 고정" 버튼을 클릭합니다. 이 단계에서는 아직 아무것도 실행되지 않습니다.

💡 여기서: 계획이 이상해 보이면 채팅으로 다시 물어볼 수 있음

3️⃣ 실제 실행 시작

페이지: / (홈)

수동

"실제 실행 시작" 버튼을 누르는 순간 AI 도구들이 실제로 코드를 작성하기 시작합니다. 이 버튼을 누르기 전까지는 100% 안전합니다.

⚠️ 주의: 이 버튼을 누르면 AI가 실제로 작업을 시작합니다. 계획을 한 번 더 확인하세요.

4️⃣ AI 도구 자동 실행

백그라운드 자동 진행

자동

시스템이 로드맵에 있는 작업들을 하나씩 Claude Code, Codex 같은 AI 도구들로 보냅니다. 각 작업에 맞는 도구를 자동으로 선택합니다.

  • • 복잡한 설계 → Claude Code (강함)
  • • 버그 수정, 타입 에러 → Codex (빠름)
  • • UI 디자인 → Antigravity (시각적)

5️⃣ 위험 작업 자동 감지 및 승인

페이지: /orchestration (오케스트레이션)

반자동

안전한 작업은 자동으로 진행되지만, 위험한 작업(서버 배포, DB 수정, 파일 삭제 등)이 감지되면 먼저 당신에게 승인을 요청합니다.

💡 예시: "git push 하려고 합니다. 승인하시겠습니까?" → 버튼 클릭 → 실행

6️⃣ 결과 검증

페이지: /result-review

수동

각 AI 도구의 작업 결과가 나오면, 코드가 제대로 작성되었는지 당신이 검증합니다. "통과", "수정 필요", "차단", "QA" 등으로 표시할 수 있습니다.

💡 여기서: 결과가 마음에 안 들면 피드백 입력 → AI가 수정 작업 자동 시작

7️⃣ 다음 단계 자동 추천 및 진행

페이지: /plan (로드맵)

자동

시스템이 자동으로 로드맵을 업데이트하고 "다음으로 이 작업을 해야 할 것 같습니다" 라고 추천합니다. 로드맵은 실시간으로 업데이트됩니다.

8️⃣ 완료

페이지: /plan (로드맵)

수동

로드맵의 모든 단계가 "완료"로 표시되면, 기본 개발은 완료되는 것입니다. 이 결과를 GitHub에 푸시하거나, Obsidian 메모리에 학습 내용을 저장할 수 있습니다.

📈 자동화 비율

완전 자동 (관찰만 함) 약 40%
반자동 (버튼 1~2번) 약 30%
수동 (판단/승인 필요) 약 30%

각 페이지 사용 가이드

15개 페이지를 언제, 어떻게 사용하는지

🏠 기획 채팅 / (홈)

언제 쓰나: 새로운 프로젝트를 시작할 때, 또는 현재 계획을 수정하고 싶을 때

뭘 하나: 아이디어를 텍스트로 설명 → AI가 로드맵을 자동으로 생성 → "계획 고정" → "실제 실행 시작" 버튼으로 진행

주요 버튼: "메시지 전송" → "계획 고정" → "실제 실행 시작"

🗺️ 로드맵 제어실 /plan

언제 쓰나: 현재 진행 상황을 확인하고 싶을 때, 다음 할 일을 알고 싶을 때

뭘 하나: 전체 로드맵을 한 눈에 보기 → 각 단계의 진행률 확인 → 현재 AI 도구의 상태 확인 → 다음 추천 작업 확인

핵심 정보: Phase별 진행률, 다음 작업 추천, 에이전트 상태, 위험도 레이더

📊 통합 대시보드 /dashboard

언제 쓰나: 여러 프로젝트를 진행할 때, 전체 진행 상황을 한눈에 보고 싶을 때

뭘 하나: 모든 프로젝트의 KPI(성공률, 작업 수 등) 한눈에 보기 → 최근 활동 확인 → 프로젝트별 필터링

자동 갱신: 30초마다 자동으로 최신 정보로 업데이트됨

🔄 오케스트레이션 /orchestration

언제 쓰나: 자세한 작업 승인, 위험 작업 검토, 실시간 모니터링이 필요할 때

뭘 하나: 대기 중인 작업 목록 보기 → 위험 작업 승인/거부 → "안전한 작업 자동 실행" 버튼으로 일괄 처리 → 로그 모니터링

주요 탭: 결정, 큐, 결과, 승인, 진행상황, 피드백, 모니터, 로그, 지표

📁 프로젝트 관리 /projects

언제 쓰나: 새 프로젝트를 등록하거나, 기존 프로젝트 정보를 수정할 때

뭘 하나: 프로젝트 이름, 설명, 기술 스택 입력 → "프로젝트 생성" → 이후 기획 채팅에서 사용 가능

저장되는 정보: 프로젝트명, 설명, GitHub 링크, 기술 스택

🤖 에이전트 상태 설정 /agent-status

언제 쓰나: Claude나 Codex가 사용 불가능할 때, 또는 토큰이 부족할 때

뭘 하나: 각 AI 도구(Claude Code, Codex, Antigravity)의 상태를 "가능", "토큰 부족", "쉬는 중", "차단" 등으로 표시

영향: 이 설정에 따라 다음 작업을 할 AI 도구가 자동으로 선택됨

✅ 결과 검증 /result-review

언제 쓰나: AI 도구의 작업 결과가 나왔을 때, 그 결과가 좋은지 나쁜지 판단해야 할 때

뭘 하나: AI 결과 붙여넣기 → "통과", "수정 필요", "차단", "QA 요청" 중 선택 → 피드백 입력 → 저장

중요: 당신의 판단이 다음 작업 추천에 반영됨

🧠 Hermes 패킷 /hermes-packets

언제 쓰나: 작업을 위임하고 싶을 때, 또는 시스템의 추천을 자세히 읽고 싶을 때 (실행은 안 됨)

뭘 하나: 자동으로 생성된 작업 패킷 종류 선택 → 마크다운으로 된 상세 설명 읽기 → 필요하면 복사해서 다른 곳에 사용

주의: ⚠️ "Hermes는 실행되지 않습니다" - 이것은 조언만 제공합니다

📝 핸드오프 /handoffs

언제 쓰나: AI 도구 간에 작업을 넘길 때, 또는 다른 사람에게 상황을 설명해야 할 때

뭘 하나: 시스템이 자동 생성한 핸드오프 문서 확인 → 필요하면 복사해서 다음 도구에 전달

내용: 지금까지 한 일, 바뀐 파일, 다음 할 일, 주의사항

📋 작업 리포트 /reports

언제 쓰나: AI 도구가 작업을 완료했을 때, 그 결과를 기록으로 남기고 싶을 때

뭘 하나: 작업 이름, 결과, 소요 시간, 이슈 등을 입력 → 저장 → 나중에 조회 가능

활용: 작업 이력 추적, 패턴 분석, 성과 평가

🚀 실행 워크벤치 /workbench

언제 쓰나: 특정 작업을 지금 바로 실행하고 싶을 때 (고급 사용자)

뭘 하나: 체크리스트 완료 → "승인" 버튼 → AI가 즉시 코드 작성 시작 → 실시간 로그 보기

매우 위험: 이 페이지는 고급 사용자용입니다

📦 Context Pack /context-pack

언제 쓰나: 세션이 길어져서 토큰이 부족할 때, 또는 새 AI 도구로 전환할 때

뭘 하나: "Context Pack 생성" 버튼 → 지금까지의 모든 정보가 정렬된 문서 생성 → 다음 도구에 붙여넣기

포함: 지금까지 한 일, 바뀐 파일, 주의사항, 다음 할 일

💾 메모리 & 인사이트 /memory

언제 쓰나: 배운 점을 기록하고 싶을 때, 또는 다음 프로젝트에서 참고하고 싶을 때

뭘 하나: 인사이트 입력 → 유형 선택(결정, 실패 사례, 프롬프트 팁 등) → Obsidian 포맷으로 저장

활용: Obsidian 데스크탑 앱과 동기화 가능

🔧 기술 어드바이저 /advisor

언제 쓰나: "이 기술을 쓸까 저 기술을 쓸까?" 같은 기술 질문이 있을 때 (실행 안 함)

뭘 하나: 기술 질문 입력 → AI가 상황에 맞는 조언 제공 → 읽고 참고하기 (아무것도 실행 안 됨)

목적: 의사결정 앞에 빠르게 조언 얻기

📄 프롬프트 컴파일러 /prompt-compiler

언제 쓰나: AI 도구에 줄 프롬프트를 수동으로 작성하고 싶을 때

뭘 하나: 작업 설명 입력 → 시스템이 "이런 AI 도구를 쓰세요, 이런 리스크가 있으니 주의하세요" 라고 조언 → 복사해서 사용

활용: 자동 실행 말고 수동으로 더 세밀하게 제어하고 싶을 때

⚠️ 구현됐지만 사용되지 않는 기능

코드는 있지만 실제로 쓰이지 않고 있는 부분들

🔴 워크플로우에 연결 안 된 화면들

이 화면들은 만들어져 있지만 어디서도 이 화면으로 들어갈 수 있는 버튼이 없습니다.

1. 승인 게이트 (Approval Gate Panel)

뭘 하려고 했나: 위험한 작업(운영 서버에 배포, 데이터베이스 수정 등)을 실행하기 전에 체크리스트로 다시 한 번 확인하는 화면

어디서 쓰려고 했나: 오케스트레이션 페이지의 탭 중 하나

현재 상태: ✅ 체크리스트 UI와 승인 로직 다 만들어져 있지만, 오케스트레이션 페이지에 탭으로 붙지 않았음

2. 자동 결정 패널 (Auto Decision Panel)

뭘 하려고 했나: AI가 작업 결과를 보고 자동으로 "이건 통과입니다", "이건 실패하려고 합니다" 같이 판단하는 화면에서 그 판단 내용을 보기

어디서 쓰려고 했나: 오케스트레이션 페이지 → 검증 탭

현재 상태: ✅ AI 판단 로직은 작동하지만, UI에서 보는 화면이 없음

3. 칸반 보드 (Kanban Board)

뭘 하려고 했나: 작업 카드를 드래그 드롭해서 "대기중" → "진행중" → "완료" 로 옮기는 시각적인 보드

어디서 쓰려고 했나: 로드맵 페이지 또는 별도 페이지에서 칸반 보드로 작업 관리

현재 상태: ⚠️ 개별 카드 컴포넌트는 쓰이고 있지만, 전체 보드를 볼 수 있는 페이지가 없음

4. 모니터 패널 (Monitor Panel - 구버전)

뭘 하려고 했나: Hermes AI가 현재 작업 상황을 모니터링하고 조언하는 화면 (예: "지금 여기 위험 신호 있으니까 주의하세요")

어디서 쓰려고 했나: 별도의 모니터링 페이지

현재 상태: 🔄 이 기능은 새로운 버전(오케스트레이션 페이지 내 "모니터" 탭)으로 대체됨. 구버전은 사용 안 함

5. 프로젝트 상태 카드 (Project Status Card)

뭘 하려고 했나: 프로젝트 목록에서 각 프로젝트의 진행률, 마지막 업데이트 시간, AI 도구 상태 등을 한 카드에 보여주기

어디서 쓰려고 했나: /projects 페이지 → 프로젝트 목록

현재 상태: ✅ 카드 컴포넌트 만들어짐 → 하지만 프로젝트 페이지에는 로드되지 않음

6. 로드맵 상태 위젯 (Roadmap Status Widget)

뭘 하려고 했나: 대시보드의 작은 영역에 현재 로드맵 진행률을 시각적으로 보여주는 위젯

어디서 쓰려고 했나: /dashboard 페이지의 상단

현재 상태: ✅ 위젯 코드 있음 → 대시보드에 배치 안 됨

7. 스케줄링 모드 선택 (Scheduling Mode Panel)

뭘 하려고 했나: 여러 작업을 어떻게 실행할지 선택하는 화면

옵션:

  • • "한 번에 하나씩" (순서대로)
  • • "동시에 여럿" (병렬 실행)
  • • "릴레이 방식" (A 끝나면 B 시작)

현재 상태: ✅ 로직이 다 구현되었지만, 워크벤치 페이지에 UI가 붙지 않음

8. 에이전트 능력 목록 (Agent Capability List)

뭘 하려고 했나: 각 AI 도구(Claude, Codex, Antigravity)가 어떤 작업에 강한지 보여주는 목록

어디서 쓰려고 했나: /agent-status 페이지에서 에이전트를 선택할 때, "이 AI는 UI 디자인에 강합니다" 같은 설명

현재 상태: ✅ 능력 정보 다 정의되었지만, 페이지에 표시 안 됨

9. 방향성 오케스트레이터 (Direction Orchestrator - 구버전)

뭘 하려고 했나: 초기 버전에서 아이디어를 입력하면 작업으로 변환하는 화면

현재 상태: 🔄 이 기능은 "기획 채팅" 으로 완전히 대체되어 더 이상 쓰이지 않음

10. 모니터 컴포넌트 폴더 전체

뭘 하려고 했나: Context Pack 빌더, 핸드오프 빌더, Obsidian 메모리 등을 모니터링하는 UI

현재 상태: 🔄 이 기능들이 "Hermes" 폴더로 이동되고 통합됨. 구 버전은 불필요

⚫ 코드는 있지만 작동하지 않는 기능들

이 기능들은 구현이 완료되었지만, 필요한 외부 설정이나 활성화가 되지 않아 실제로는 작동하지 않습니다.

1. 텔레그램 승인 알림 (Telegram Approval Bot)

뭘 하려고 했나: 위험한 작업(서버 배포, DB 삭제 등)이 생기면 자동으로 당신의 텔레그램으로 "이 작업 승인하시겠습니까?" 라는 메시지를 보내기

예시: 텔레그램에 "⚠️ git push 하려고 합니다. 승인/거부" 버튼이 달린 메시지 → 클릭 → 즉시 작업 실행 또는 차단

현재 상태: ✅ 텔레그램 API 연동 코드는 완전히 구현되었지만, 실제 텔레그램 봇 토큰이 설정되지 않아 발송이 안 됨

2. 디스코드 웹훅 알림 (Discord Webhook)

뭘 하려고 했나: 위험한 작업이 생기면 디스코드 채널에 "📋 작업 승인 카드" 를 보내기

목적: 팀 채널에서 실시간으로 승인 요청을 받고 빠르게 응답하기

현재 상태: ✅ 코드는 완성 → 실제 Discord 채널 설정이 없어서 mock (가짜) 상태. 실제 발송 안 됨

3. Hermes CLI 자동 실행 (Hermes Auto-Execution)

뭘 하려고 했나: Hermes 패킷 화면에서 보이는 작업들을 실제로 자동 실행하기

예시: "실패한 테스트 다시 실행" 패킷을 보고 있을 때 "이거 자동으로 실행해줄까?" 버튼이 있었음

현재 상태: ✅ Hermes CLI 연동 코드는 만들어졌지만, 안전상 이유로 UI에는 "⚠️ 실행되지 않습니다" 라고 표시. 실제 실행 불가

4. 에이전트 가용성 자동 감지 (Agent Capability Auto-Detection)

뭘 하려고 했나: Claude, Codex가 현재 설치되어 있고 사용 가능한지 자동으로 체크하기

목적: 당신이 매번 "Claude는 토큰이 부족합니다" 라고 수동으로 입력할 필요 없이 자동으로 감지

현재 상태: ✅ 자동 감지 함수는 구현되었지만, 실제로는 사용자가 /agent-status 페이지에서 수동으로 상태를 설정해야 함

📌 정리

  • ⚠️ 미연결 화면 10개: UI는 다 만들어졌지만 어디서도 갈 수 있는 버튼이 없음. "페이지 사용 가이드" 탭에 나오는 15개 페이지만 실제로 쓰임.
  • ⚫ 미활성 자동화 4개: 코드와 API 엔드포인트는 완전히 구현되었지만, 외부 설정(텔레그램 토큰, 디스코드 웹훅, Hermes 활성화 등)이 없어서 실제로 작동하지 않음.
